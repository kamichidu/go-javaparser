= go-javaparser Event Stream Design Specification
:toc: left
:sectnums:
:source-highlighter: coderay

This document defines the Go language physical data type definitions (schema), emission triggers, and integration protocols for event transmission of the "SourceEvent Stream (unidirectional event stream)" emitted by `go-javaparser` throughout the syntactic analysis phase.

---

== Independent Event Projection Philosophy and Complete Elimination of ast Dependency

This event stream is an **independent projection layer (Event Projection)** that embodies the "Prioritize streaming over materialization" design constitution to the absolute limit.

* **Elimination of dependency on the ast package**:
  To eliminate unnecessary package coupling or circular dependencies, this package (`event`) does not import the `ast` package at all.
  Data types such as physical coordinates `Range`, type category `TypeKind`, and formal parameter information `Parameter` are all retrieved from the `syntax` package, achieving immutable streaming completely isolated from the AST Projection.
* **AST-independent Direct Streaming**:
  This event stream is not generated by traversing an intermediate AST constructed and materialized in memory.
  Instead, as the `Parser Core` (syntactic analyzer core) processes tokens and discovers each syntactic element (class, method, import, etc.) on the fly, **it pushes events directly to `event.EventSink` without any intermediate node allocation**.

---

== Subscription Model and EventSink Interface

Events emitted from the Parser are pushed to downstream consumers (indexers, LSP servers, static analysis tools, etc.) through the `EventSink` interface.

[source,go]
----
package event

import "github.com/kamichidu/go-javaparser/syntax"

// EventSink is an interface for sequentially receiving events occurring during the parsing process
type EventSink interface {
    // Emit sends events synchronously or asynchronously
    Emit(evt SourceEvent) error
}

// SubscriptionPolicy is a bitmask or policy controlling which events the subscriber wants to receive
type SubscriptionPolicy uint32

const (
    // DefaultPolicy (SubscribeDeclarations) is the default policy that always emits core declaration events (Type, Method, Field, etc.).
    // Consumers operate under this default policy if nothing is explicitly specified.
    DefaultPolicy SubscriptionPolicy = 1 << iota

    // SubscribeOccurrences is an optional policy for receiving identifier occurrence information (OccurrenceEvent).
    SubscribeOccurrences
)
----

=== Subscription Policy Control
1. **Declaration events (Core / DefaultPolicy)**:
   Since they are essential for generating basic structure information such as type, member, and import declarations, they are defined as a **default policy (Default Policy) that is always emitted**. No matter what subscription configuration the consumer chooses, these declaration events are always delivered.
2. **Occurrence information events (OccurrenceEvent / SubscribeOccurrences)**:
   Occurrence information, which is useful for reference locations and definition source modifications (e.g. Rename), is treated as an **optional subscription policy** because the amount of data is large.
   Only when the downstream consumer explicitly enables the `SubscribeOccurrences` policy does the Parser Core parse, extract, and emit variable and type occurrence information within methods. If not enabled, the Parser Core completely skips syntactic parsing and allocation of corresponding local expressions and blocks.

== Event Definitions (SourceEvent)

All event structures implement the common `SourceEvent` interface.

[source,go]
----
package event

import "github.com/kamichidu/go-javaparser/syntax"

type EventType string

// SourceEvent is an interface that all events must satisfy
type SourceEvent interface {
    Type() EventType
    GetRange() syntax.Range
}
----

The detailed design of event structures depending only on the common `syntax` package is defined below.

=== File Boundary Events
StartFileEvent::
  Indicates the start of parsing for the target file (`SourceID`).
EndFileEvent::
  Indicates that parsing of the entire file has completed successfully without errors (commit trigger for the entire file).

[source,go]
----
type StartFileEvent struct {
    SourceID string // Unique identifier such as file path
}

func (e StartFileEvent) Type() EventType        { return "StartFile" }
func (e StartFileEvent) GetRange() syntax.Range { return syntax.Range{} }

type EndFileEvent struct {
    SourceID string
}

func (e EndFileEvent) Type() EventType        { return "EndFile" }
func (e EndFileEvent) GetRange() syntax.Range { return syntax.Range{} }
----

=== Declaration Events (Core)
PackageDeclEvent::
  Observation of a package name definition.
ImportDeclEvent::
  Observation of an import definition.
TypeDeclEvent::
  Observation of declarations of classes, interfaces, enums, records, and annotation types.
FieldDeclEvent::
  Observation of field declarations or enum constants (Enum Constant).
MethodDeclEvent::
  Observation of method declarations.
ConstructorDeclEvent::
  Observation of constructor declarations.

[source,go]
----
type PackageDeclEvent struct {
    Name  string
    Range syntax.Range
}

func (e PackageDeclEvent) Type() EventType        { return "PackageDecl" }
func (e PackageDeclEvent) GetRange() syntax.Range { return e.Range }

type ImportDeclEvent struct {
    Name     string
    IsStatic bool
    IsStar   bool
    Range    syntax.Range
}

func (e ImportDeclEvent) Type() EventType        { return "ImportDecl" }
func (e ImportDeclEvent) GetRange() syntax.Range { return e.Range }

type TypeDeclEvent struct {
    Kind        syntax.TypeKind
    Name        string
    Modifiers   []string
    Annotations []string // List of annotation names
    Range       syntax.Range
}

func (e TypeDeclEvent) Type() EventType        { return "TypeDecl" }
func (e TypeDeclEvent) GetRange() syntax.Range { return e.Range }

type FieldDeclEvent struct {
    Name        string
    DataType    string
    Modifiers   []string
    IsEnumConst bool
    Range       syntax.Range
}

func (e FieldDeclEvent) Type() EventType        { return "FieldDecl" }
func (e FieldDeclEvent) GetRange() syntax.Range { return e.Range }

type MethodDeclEvent struct {
    Name       string
    ReturnType string
    Modifiers  []string
    Parameters []*syntax.Parameter // Directly references syntax.Parameter
    Range      syntax.Range
}

func (e MethodDeclEvent) Type() EventType        { return "MethodDecl" }
func (e MethodDeclEvent) GetRange() syntax.Range { return e.Range }

type ConstructorDeclEvent struct {
    Name       string
    Modifiers  []string
    Parameters []*syntax.Parameter
    Range      syntax.Range
}

func (e ConstructorDeclEvent) Type() EventType        { return "ConstructorDecl" }
func (e ConstructorDeclEvent) GetRange() syntax.Range { return e.Range }
----

=== Differential Update (Partial Parse) Events
StartDeltaScopeEvent::
  Indicates the start of a local parse (`Partial Parse`) and states the target `MergeScope` (identification/signature representation of the parent method, etc.).
EndDeltaScopeEvent::
  Indicates the successful completion of a local parse (`Partial Parse`) (partial commit trigger).

[source,go]
----
type StartDeltaScopeEvent struct {
    SourceID   string
    MergeScope string // Identification key of the target scope to update (e.g. "M:com.example.Utils#getGreeting()V")
    Range      syntax.Range
}

func (e StartDeltaScopeEvent) Type() EventType        { return "StartDeltaScope" }
func (e StartDeltaScopeEvent) GetRange() syntax.Range { return e.Range }

type EndDeltaScopeEvent struct {
    SourceID   string
    MergeScope string
    Range      syntax.Range
}

func (e EndDeltaScopeEvent) Type() EventType        { return "EndDeltaScope" }
func (e EndDeltaScopeEvent) GetRange() syntax.Range { return e.Range }
----

=== Local Scope and Variable Declaration Events
ScopeEnterEvent::
  Entering a local scope such as a local block (curly braces `{}`), method body, or lambda.
ScopeLeaveEvent::
  Leaving a local scope.
LocalDeclEvent::
  Observation of a method parameter or local variable declaration.

[source,go]
----
type ScopeEnterEvent struct {
    Range syntax.Range
}

func (e ScopeEnterEvent) Type() EventType        { return "ScopeEnter" }
func (e ScopeEnterEvent) GetRange() syntax.Range { return e.Range }

type ScopeLeaveEvent struct {
    Range syntax.Range
}

func (e ScopeLeaveEvent) Type() EventType        { return "ScopeLeave" }
func (e ScopeLeaveEvent) GetRange() syntax.Range { return e.Range }

type LocalDeclEvent struct {
    Name     string
    DataType string
    Range    syntax.Range
}

func (e LocalDeclEvent) Type() EventType        { return "LocalDecl" }
func (e LocalDeclEvent) GetRange() syntax.Range { return e.Range }
----

=== Anomaly/Error Events
ParseErrorEvent::
  Indicates that a grammatical/syntax error has occurred.

[source,go]
----
type ParseErrorEvent struct {
    SourceID string
    Message  string       // Error message
    Range    syntax.Range // Occurrence of error
}

func (e ParseErrorEvent) Type() EventType        { return "ParseError" }
func (e ParseErrorEvent) GetRange() syntax.Range { return e.Range }
----

== Event Ordering and Emission Lifecycle Steps

A series of standard steps when the Parser Core fully parses a single Java file and emits events is executed in the following order:

1. **File Start Indication**: Emits `StartFileEvent`.
2. **Package Declaration**: Emits `PackageDeclEvent` (if present).
3. **Import Declarations**: Emits multiple `ImportDeclEvent`s in the order they are detected.
4. **Type Declarations**:
   a. Emits `TypeDeclEvent` at the start of a class or interface.
   b. Emits class members (`FieldDeclEvent`, `MethodDeclEvent`, etc.) in the order they are detected.
   c. When entering a method body, emits local variables and scope events nested, such as `ScopeEnterEvent` -> `LocalDeclEvent` -> `ScopeLeaveEvent` (only when occurrence subscription is enabled).
5. **File End Indication**: If there are no parse errors, finally emits `EndFileEvent` to trigger a commit of indexes or temporary storage.

=== Interruption Handling on ParseErrorEvent (v1 Specification Constraints)
When a syntactic/grammatical error occurs, the Parser Core emits a `ParseErrorEvent`.
* **v1 Constraints**:
  In the initial version (v1) specification, at the moment a syntax error occurs, the Parser Core **immediately and completely interrupts/terminates** subsequent parsing and stream delivery.
  This is a design constraint assuming the incompleteness of syntax skipping and autonomous error recovery in v1, and we plan to introduce "advanced error recovery (Error Recovery)" in v2 and later to skip invalid tokens and continue parsing and streaming even after an error occurs.
