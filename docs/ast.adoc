= go-javaparser Source AST Design Specification
:toc: left
:sectnums:
:source-highlighter: coderay

This document defines the structure, node definitions, and abstraction mapping rules from the Java Language Specification (JLS) of the "Source AST" (Declaration-Oriented Lightweight Abstract Syntax Tree) constructed in memory by `go-javaparser` during syntactic analysis.

---

== Design Policy: Lightweight and Specialized for Declaration Structures

The AST of `go-javaparser` is not intended for building compilers, but is a **"declaration-oriented lightweight data model"** for processing symbol search, definition jump, auto-completion, hover display, and outline extraction required by LSPs (Language Server Protocol) and static analysis tools in milliseconds.

=== Comparison with Concrete Syntax Tree (CST)
Below is a comparison between the full concrete syntax tree generated by a compiler (such as javac) and the `Source AST` generated by `go-javaparser`.

[cols="1s,2,2", options="header"]
|===
| Evaluation Axis | Compiler Concrete Syntax Tree (CST / Full AST) | go-javaparser Declaration-Oriented AST (Declaration-Oriented AST)

| Main Purpose
| Bytecode generation, strict static type checking
| Ultra-low-latency symbol index construction, declaration projection for LSPs, etc.

| Syntax Detail Level
| 100% complete reproduction of operator precedence, local expression trees, semicolons, curly braces, etc.
| Only declaration parts of classes, methods, variables, imports, and annotations (annotations)

| Parsing Speed
| Relatively slow (with complete dependency resolution and error validation)
| Extremely fast (allows skipping unnecessary method bodies and expressions)

| Memory Consumption
| Massive (huge number of nodes)
| Minimal (discards unnecessary syntax nodes and keeps them flat)

| Error Tolerance
| Parsing stops on error, or requires complex recovery
| Skips incomplete brackets or tokens in mid-write, rescuing only declaration facts
|===

== AST Structure and syntax Common Type System

To establish package boundaries that eliminate circular references, all physical coordinate information, and immutable identification data types for types and arguments, are consolidated in the independent `syntax` package (common type system).

[source,go]
----
package syntax

// Position represents a 1-based line and column within a source file
type Position struct {
    Line int // 1-based
    Col  int // 1-based
}

// Range represents a start and end position within a source file
type Range struct {
    Start Position
    End   Position
}

// TypeKind represents categories such as classes or interfaces
type TypeKind string

const (
    KindClass          TypeKind = "class"
    KindInterface      TypeKind = "interface"
    KindEnum           TypeKind = "enum"
    KindRecord         TypeKind = "record"
    KindAnnotationType TypeKind = "annotation"
)

// Parameter is a common DTO representing formal parameters of a method or constructor
type Parameter struct {
    Name        string
    Type        string
    Annotations []string
    Modifiers   []string
    Range       Range
}
----

== AST Node Definitions (ast Package)

The core nodes making up the Source AST are type-defined in the `ast` package by importing and referencing `syntax` common types as follows:

[source,go]
----
package ast

import "github.com/kamichidu/go-javaparser/syntax"

// Node is a common interface that all AST nodes must satisfy
type Node interface {
    GetRange() syntax.Range
}

// File is the root node of a source file
type File struct {
    Path     string
    Package  *Package
    Imports  []*Import
    Types    []*TypeDecl
    Range    syntax.Range
}

// Package represents a package declaration
type Package struct {
    Name  string // e.g. "com.example.utils"
    Range syntax.Range
}

// Import represents an import declaration
type Import struct {
    Name     string // e.g. "java.util.Map"
    IsStatic bool   // Whether "static" keyword is present
    IsStar   bool   // Whether trailing ".*" is present
    Range    syntax.Range
}

// TypeDecl represents a type declaration (class, interface, etc.)
type TypeDecl struct {
    Kind        syntax.TypeKind
    Name        string
    Modifiers   []string
    Annotations []*Annotation
    Generics    []*TypeParam
    Extends     []string
    Implements  []string
    Members     []MemberNode
    Range       syntax.Range
}

// MemberNode is an interface for members that can be declared within a type
type MemberNode interface {
    Node
    isMember()
}

// FieldDecl represents a field declaration
type FieldDecl struct {
    Name        string
    Type        string
    Modifiers   []string
    Annotations []*Annotation
    IsEnumConst bool        // true if it is an Enum constant
    Range       syntax.Range
}

// MethodDecl represents a method declaration
type MethodDecl struct {
    Name        string
    ReturnType  string
    Modifiers   []string
    Annotations []*Annotation
    Generics    []*TypeParam
    Parameters  []*syntax.Parameter // References the syntax.Parameter common type
    Exceptions  []string
    Body        *Block
    Range       syntax.Range
}

// ConstructorDecl represents a constructor declaration
type ConstructorDecl struct {
    Name        string
    Modifiers   []string
    Annotations []*Annotation
    Parameters  []*syntax.Parameter
    Exceptions  []string
    Body        *Block
    Range       syntax.Range
}

// LocalVarDecl represents a local variable declaration within a block
type LocalVarDecl struct {
    Name        string
    Type        string
    Modifiers   []string
    Range       syntax.Range
}

// Block represents a block enclosed in curly braces, or a scope boundary
type Block struct {
    Locals []Node
    Range  syntax.Range
}

// Annotation represents an annotation attached to a class or member
type Annotation struct {
    Name  string
    Range syntax.Range
}

// TypeParam represents generics (type parameter)
type TypeParam struct {
    Name   string
    Bounds []string
    Range  syntax.Range
}
----

== Lightweight Mapping Rules for Java 11-21 Syntax Elements

`go-javaparser` smartly maps new declaration syntax introduced in modern Java (Java 11 to 21) into the flat `TypeDecl` / `FieldDecl` design shown above, without expanding complex node hierarchies.

Record::
  The `Kind` of `TypeDecl` is set to `syntax.KindRecord`.
  Record components (header parameters) are mapped and expanded implicitly into private final `FieldDecl`s and public getter `MethodDecl`s, or are parsed equivalent to constructor parameters (`syntax.Parameter`) and included in `Members`.

AnnotationType (`@interface`)::
  The `Kind` of `TypeDecl` is set to `syntax.KindAnnotationType`.
  Annotation elements (e.g., `String value() default "";`) are parsed as `MethodDecl`s with a return type.

Enum::
  The `Kind` of `TypeDecl` is set to `syntax.KindEnum` (or `syntax.KindKindEnum` if defined that way).
  Enum constants (e.g., `RED, BLUE, GREEN;`) are registered in `Members` as `FieldDecl`s with the `IsEnumConst = true` flag, distinguishing them from normal fields there.

Nested Type (Inner Classes, etc.)::
  In Java, a class can be defined inside another class. This is supported by designing `TypeDecl` itself to satisfy the `MemberNode` interface, directly holding the nested `TypeDecl` as a tree structure inside `TypeDecl.Members`.
